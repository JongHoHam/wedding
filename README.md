# 제주 모바일 청첩장

사진 중심의 한국어 모바일 청첩장 검토용 시안입니다. 기존 MCP 서버와 독립된 React + Vite 정적 사이트이며, 아직 외부 배포하지 않았습니다.

## 실행

Node.js 22 이상 권장. 이 폴더에서 실행합니다.

```powershell
npm ci
npm run dev
```

- 청첩장: http://127.0.0.1:5173/
- 공개 디자인 100종과 제안: http://127.0.0.1:5173/?view=research
- 식장 지도 전용 화면: http://127.0.0.1:5173/?view=location
- 날짜/공유/참조 자료 테스트: `npm test`
- 배포 빌드: `npm run build`
- Secret 빌드 비노출 검증(가상 데이터): `npm run test:private-build`

## 실제 정보로 교체

`src/config.mjs`는 공개 가능한 기본값과 예식일·사진·식장 설정입니다. 실제 이름, 연락처, 계좌는 아래 Secret 또는 Git에서 제외된 `private-config.local.json`에 입력합니다. 공개 설정 파일에 실제 개인정보를 다시 넣지 마세요. 예식일과 공개용 카카오 JavaScript 키는 기본 설정을 유지하며 Secret으로 덮어쓸 수도 있습니다.

1. 예식 날짜는 `2027-05-22T12:00:00+09:00`처럼 한국 시간 오프셋을 유지합니다.
2. 비공개 JSON의 `groom`, `bride`, `accounts`를 수정합니다. `title`, `description`, `date`도 함께 바꿉니다.
3. 본인 사진과 사용권을 확보한 음악을 `public` 아래 배치합니다. `hero`, `gallery`, `shareImage`, `musicUrl`은 `./images/...` 같은 상대 경로를 사용합니다.
	- `gallery` 배열에 `{ src: "./images/photo-06.jpg", alt: "사진 설명" }` 형식으로 총 20장까지 등록합니다. 배열 순서대로 첫 5장과 나머지 가로 갤러리를 구성합니다.
	- 샘플 사진 20장이 기본 등록되어 있으며, 사진 추가/업로드 버튼은 없습니다. 실제 배포 사진은 파일과 `gallery` 설정에서 교체하세요.
4. 식장은 중문컨벤션센터 5층 오션뷰 홀로 설정했습니다. 지도·길찾기 목적지에도 중문컨벤션센터를 사용합니다. 하차 입구와 하객 주차 조건은 별도 확인이 필요합니다.
5. 버스 실제 노선 GeoJSON과 정류장 좌표를 확보해 `routes[].points`와 `stops`를 교체합니다. `points`는 `[위도, 경도]` 순서입니다. 현재 버스선은 도로를 따른 노선이 아닙니다. 검증 전 `verified: false`를 유지합니다.
6. 두 버스 노선은 `public/images/bus-600-601.png`의 공식 통합 시간표를 사용합니다. 교체할 때는 `routes[].timetable`의 상대 경로를 함께 수정합니다. 웹 경로에는 `public/`을 붙이지 않습니다. 빈 문자열이면 280px 빈 영역을 표시합니다. 사진 파일과 설정을 함께 빌드·배포하세요.
7. `siteUrl`에 저장소 경로를 포함한 최종 HTTPS 주소와 마지막 `/`를 입력합니다. 예: `https://USER.github.io/wedding/`.
8. 카카오 JavaScript 키를 `kakaoJsKey`에 입력하고 카카오 개발자 콘솔에 JavaScript SDK 도메인과 제품 링크 웹 도메인을 등록합니다. JavaScript 키는 도메인 제한을 적용하는 공개용 키입니다. REST/어드민 비밀 키를 프런트엔드에 넣지 않습니다.
9. 비공개 JSON이 적용되면 `demo: false`로 자동 전환됩니다. `npm run build`로 확인합니다. 이 설정은 실제 내용 확인을 대신하지 않습니다.

## 첫 화면 영상

- `src/config.mjs`의 `heroVideo`는 `./videos/wedding.mp4`를 사용합니다. 빈 문자열로 설정하면 사진만 표시합니다.
- 원본은 변경하지 않고 배포용 사본을 `public/videos/wedding.mp4`로 생성했습니다. 약 47초 전체 길이, 1920x1080 H.264, 웹 로딩용 faststart, 음성 트랙 제거, 약 7.5MB입니다.
- 첫 진입 문구 애니메이션이 끝나거나 건너뛰면 인라인·무음·반복 재생을 요청합니다. 영상의 첫 프레임이 준비될 때까지 진입 화면을 유지한 뒤, 사진 노출이나 영상 페이드 없이 영상 위로 진입 화면을 걷어냅니다. 동작 줄이기 설정은 진입 효과를 생략합니다. 영상은 별도 일시정지 버튼으로 멈출 수 있습니다.
- 자동 재생이 차단되면 기존 사진과 재생 버튼을 표시합니다. 영상 파일이 없거나 해독에 실패하면 사진만 표시합니다. 배경음 스피커를 눌러도 영상 음소거는 해제되지 않습니다.
- 첫 화면은 초기 화면 높이를 채우며, 세로 화면의 영상은 중앙 기준으로 잘립니다. 상단 이니셜·지역 문구 없이 오른쪽에 스피커 버튼만 표시합니다.
- 배포하면 영상도 공개됩니다. 실제 카카오톡·iOS의 자동 재생은 앱 설정·절전 모드에 따라 제한될 수 있습니다.

## GitHub Secrets로 개인정보 관리

1. 저장소 Settings > Secrets and variables > Actions에 `WEDDING_PRIVATE_CONFIG`를 등록합니다. 값은 `private-config.example.json`과 같은 JSON 객체이며 실제 정보로 교체합니다. 예시 파일 자체에는 개인정보를 넣지 않습니다.
2. 필수 항목은 `groom.name`, `bride.name`, `accounts`입니다. 계좌는 예시와 같은 side/role 조합 6개를 모두 포함해야 합니다. 공개하지 않을 은행·계좌·전화번호는 빈 문자열로 둡니다. 번호는 숫자가 아닌 문자열이어야 합니다.
3. `groom`, `bride`는 필드별 병합입니다. `name`을 입력하고 부모 이름·영문 이름을 생략하면 예시 이름을 표시하지 않도록 비웁니다. `short`가 생략되고 `name`이 있으면 `name`을 표시합니다. `accounts`는 배열 전체를 교체합니다.
4. 추가 허용 항목은 `title`, `date`, `description`, `siteUrl`, `kakaoJsKey`, `shareImage`입니다. 제목을 생략하면 신랑·신부 이름으로 만듭니다. 날짜는 생략하면 공개 기본 설정의 예식일을 사용합니다. `siteUrl`은 `https://YOUR_ID.github.io/wedding/` 형식이며 저장소 주소 `https://github.com/...`는 사용할 수 없습니다. 실제 배포 계정과 저장소 이름을 확인하세요. 알 수 없는 필드는 오류로 처리합니다.
5. Actions에서 빌드 단계에만 Secret을 환경변수로 전달합니다. Secret이 없거나 JSON/필수값이 잘못되면 배포를 중단합니다. 개인정보는 로그에 출력하지 않습니다.
6. Vite가 메모리에서 설정을 합치고 앱 코드와 공유 메타데이터를 `dist`에 생성합니다. 추적되는 `src/config.mjs`, `index.html`에는 실제 값을 기록하지 않습니다. 원본 HTML을 덮어쓰던 metadata 스크립트는 제거했습니다.
7. Secret 변경 후 Actions > Deploy Wedding Invitation > Run workflow를 실행해야 반영됩니다. Secret 수정 자체로 배포가 시작되지는 않습니다.

로컬에서는 `private-config.local.json`을 프로젝트 루트에 두면 `npm run dev`와 `npm run build`에서 읽습니다. 현재 입력되어 있던 정보는 이 파일에 보존했습니다. 이 파일은 `.gitignore`로 제외하고 개발 서버의 직접 파일 요청도 차단합니다. 값을 변경한 뒤 개발 서버를 재시작하세요. JSON이 없으면 로컬은 공개 예시로 실행되며, 환경변수 `WEDDING_PRIVATE_CONFIG`가 있으면 로컬 파일보다 우선합니다. GitHub Actions는 로컬 파일로 대체하지 않습니다.

**Secret은 공개 저장소에서만 정보를 숨깁니다. 배포된 HTML/JavaScript 및 사이트 방문자에게는 해당 정보가 공개됩니다.** 이전 커밋에 들어간 개인정보는 이 변경으로 삭제되지 않습니다. 공개 전 Git 이력과 이미 게시된 자료를 별도로 확인하세요. 로컬 JSON을 `git add -f`로 추가하거나 전체 폴더 ZIP에 포함하지 마세요. 원래 파일이 이미 Git 추적 중이었다면 `.gitignore`만으로 추적이 해제되지 않습니다.

## 모바일 동작 및 시간표 출처

- 진입 글자는 0.18초 페이드로 표시하고, 마지막 글자 표시 이후 읽을 시간을 확보한 뒤 오버레이 애니메이션 종료 이벤트로 닫습니다. 동작 줄이기 설정에서는 생략합니다.
- 구간 등장 효과는 내부 콘텐츠가 80px 아래에서 2초 동안 올라오며, 투명도 8%에서 2초 동안 페이드됩니다. 두 번째 콘텐츠부터 0.1초 간격으로 최대 0.3초 지연해 순차 등장합니다. 화면 하단 64px 안쪽에 들어온 영역을 기준으로 시작합니다. 섹션 자체의 위치와 높이는 바꾸지 않고, 움직이는 자식은 브라우저 스크롤 앵커 대상에서 제외합니다. 한 번 등장한 구간은 다시 재생하지 않으며 동작 줄이기 설정에서는 이동을 생략합니다. 전역 smooth scroll과 갤러리 스냅은 제거된 상태이며, 모달 종료 시 초점 복원으로 스크롤하지 않습니다.
- 모바일·카카오 웹뷰는 첫 진입의 화면 높이를 대문 레이아웃에 사용합니다. 상단 UI·키보드 등으로 높이만 바뀌면 대문 높이를 유지하며, 회전·분할 화면 등 가로 폭이 바뀔 때만 다시 측정합니다. 데스크톱은 높이 변경에도 반응합니다. 스크롤 좌표를 강제로 복원하거나 터치 기본 동작을 막지 않습니다. 카카오톡 자체 UI 애니메이션은 제어할 수 없으며 페이지의 추가 레이아웃 밀림만 줄입니다.
- 터치 갤러리는 브라우저 기본 가로 스크롤·관성을 사용하며 세로 페이지 스크롤을 허용합니다. 사진 hover 확대는 마우스 환경에만 적용합니다. 마우스 드래그와 키보드 확대는 유지합니다.
- Chromium 모바일 터치 환경에서 스와이프·탭·세로 스크롤·전체 진입 문구를 검증했습니다. 웹뷰 높이를 반복 변경해 대문·문서 높이·섹션 위치·스크롤 좌표가 유지되는지, 구간 등장 중 스크롤이 보정되지 않는지, 회전·동작 줄이기·데스크톱 높이 변경도 검증했습니다. 카카오톡 Android/iOS 앱 내부의 실제 기기 검증은 별도로 필요합니다.
- 시간표 출처: [제주버스정보시스템 시간표/요금](https://bus.jeju.go.kr/publicTrafficInformation/generalBusSchedule?viewtype=2) → 리무진 → 600, 601.
- [공식 Excel 원본](https://bus.jeju.go.kr/data/schedule/downScheduleExcel?gscheduleId=405067)의 공항 출발 시트는 600·601번 통합표입니다. 표의 시각·안내 문구·병합 셀을 유지해 PNG로 변환했습니다. 원본 시행일은 2024-08-01, 다운로드 확인일은 2026-09-18입니다. 미래 운행을 보장하지 않으므로 출발 전 최신표를 확인해야 합니다.
- 기존 `/publicTraffiInformation/airportBusInfo` 주소는 확인일 기준 404여서 현재 공식 메뉴를 사용했습니다.

## 공유 제약

- 일반 URL 붙여넣기의 OG 미리보기에는 임의의 버튼 2개를 강제할 수 없습니다. 버튼 2개는 카카오 공유 SDK로 보낼 때 지원됩니다.
- 두 번째 버튼은 같은 사이트의 `?view=location`으로 연결되어 식장 지도를 즉시 보여줍니다. 여기서 기본 지도 앱을 엽니다. 외부 앱 자동 실행은 OS, 설치 앱, 인앱 브라우저 정책에 따라 제한되므로 자동 실행을 보장하지 않습니다.
- 티맵/네이버지도 실제 앱 실행, 카카오내비 및 카카오 공유 전송은 Android/iOS 실기기에서 별도로 검사해야 합니다. 현재 환경에서는 실제 메시지를 발송하지 않았습니다.
- 로컬 주소는 다른 사람이나 카카오 크롤러가 접근할 수 없습니다. 배포 뒤 OG 사진 접근과 공유 캐시 갱신을 확인합니다.

## GitHub Pages 운영

**이 폴더의 내용만 별도 저장소에 올리세요. 상위 업무용 MCP 저장소, `.env`, 토큰, 고객 자료는 포함하지 마세요.**

`.github/workflows/pages.yml`은 이 폴더가 새 저장소의 루트가 된 경우를 기준으로 합니다. GitHub 저장소 Settings > Pages > Source에서 GitHub Actions를 선택합니다. 실제 정보와 `siteUrl`을 설정하고 테스트 후 `main`에 업로드하면 빌드·배포됩니다. 현재는 업로드/배포하지 않았습니다.

정적 사이트의 연락처·계좌는 페이지 및 빌드 소스에 공개됩니다. 계좌 접기는 접근 통제가 아닙니다. 공개 저장소 커밋에 개인정보를 남기지 않는 운영 방식을 검토하고 당사자 동의를 받은 정보만 게시하세요. `noindex`는 검색 노출 억제 요청일 뿐 비공개 보장이 아닙니다.

지도의 OSM 타일은 외부 네트워크가 필요하며 공개 타일 서비스 정책을 따라야 합니다. 대규모 트래픽에는 적절한 상용 지도 제공자를 선택하세요. 자가용 경로는 저장되어 있어 OSRM을 하객 접속마다 호출하지 않습니다. 실시간 길찾기는 키를 보호하는 서버/API 구성이 별도로 필요합니다.

## 추가 제안

1. **참석 여부·식사 인원**: 동행 성인/아동 수, 양가 구분, 셔틀 이용 여부. 실제 저장은 개인정보 동의·보관 기한·스팸 방지·관리자 접근 제한을 갖춘 백엔드나 외부 폼으로 연결합니다. 전송되지 않는 가짜 제출 버튼은 넣지 않았습니다.
2. **제주 하객 안내**: 항공편 지연 대비, 공항 셔틀·숙소·렌터카 반납 여유, 우천 시 동선. 항공편 도착 기준 최소 출발 권장시간도 유용합니다.
3. **접근성**: 휠체어 경로, 어르신 하차 위치, 수유실, 큰 글씨 모드. 기본 무음과 모션 줄이기는 유지합니다.
4. **예식 당일 우선 화면**: D-day에는 사진보다 식장 지도·주차·연락 버튼을 먼저 노출하도록 확장할 수 있습니다.
5. **예식 후 전환**: 감사 인사·사진 공유로 전환하고 연락처·계좌를 내려 개인정보 공개 기간을 줄입니다.

추천 우선순위는 실제 식장·교통 정확성, 연락처·계좌 확인, 참석 인원 수집, 이후 부가 기능입니다.
